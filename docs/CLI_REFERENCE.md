## `scud`

```text
Scud v3 manages dependency-aware tasks; it does not run coding agents.

Start with init, choose main/fast with models, then parse a PRD into a proposal.
Review and validate the proposal before import. Use next and show to inspect work,
update to report progress, and status --watch for polling snapshots.

Task commands output JSON by default; models and sb offer --json explicitly.
next returns only the first ready reference or null; it never claims work.
Ordinary task reads and updates need neither model credentials nor optional sb.

Exit codes: 0 success (including no ready task), 1 error, 3 revision conflict,
124 deadline exceeded, 130 cancellation. Errors are written to stderr.

See README.md for the workflow and docs/CLI_REFERENCE.md for all command help.

Usage:
  scud [command]

Examples:
  scud init
  scud models list
  scud parse product.md > proposal.json
  scud validate --input proposal.json
  scud import proposal.json
  scud next
  scud show main:1
  scud update main:1 --status in-progress
  scud status --watch

Available Commands:
  completion   Generate the autocompletion script for the specified shell
  experimental Unstable inference experiments; not part of the core API
  help         Help about any command
  import       Import a versioned JSON task document
  init         Initialize task storage without overwriting existing tasks or model defaults
  list         Export tasks as an importable JSON document
  mcp-server   Serve stateless MCP 2026-07-28 over stdio or local HTTP
  models       Discover and choose main and fast models
  next         Show the first ready task reference, or null
  parse        Propose tasks from a PRD (no changes written)
  sb           Optional sb verification and context (never executes task workers)
  show         Show one task by ID
  status       Show or watch current task readiness and status
  update       Update selected task fields
  validate     Validate current tasks or an input document without writing

Flags:
  -h, --help             help for scud
  -C, --project string   Change to directory before running
  -v, --version          version for scud

Use "scud [command] --help" for more information about a command.
```

## `scud experimental ensemble`

```text
Ask 1–16 configured main/fast model defaults independently, then synthesize
their answers with --synth main|fast. Repeating a default allows homogeneous
fan-out. No agent tools, filesystem access, coding harness or task execution is
provided: these are direct model API requests, not autonomous workers.
Supply one quoted prompt or stdin (maximum 4 MiB). Requires an initialized
project, configured defaults and provider API credentials. JSON is the default.
--parallel bounds concurrent member requests; --timeout bounds overall inference.
Failed members prevent synthesis and return a nonzero exit with diagnostics.

Usage:
  scud experimental ensemble [PROMPT] [flags]

Examples:
  scud experimental ensemble 'Review this design' --models main,fast
  scud experimental ensemble 'Compare approaches' --models main,main --synth main --parallel 2
  cat prompt.txt | scud experimental ensemble --timeout 2m

Flags:
  -h, --help               help for ensemble
      --json               JSON is the default output
      --models strings     main/fast defaults (1–16); repeat a default for homogeneous fan-out (default [main,fast])
      --parallel int       Maximum parallel model requests (1–16) (default 2)
      --synth string       Model default for synthesis: main or fast (default "main")
      --timeout duration   Overall inference timeout (default 5m0s)

Global Flags:
  -C, --project string   Change to directory before running
```

## `scud mcp-server`

```text
Stateless MCP 2026-07-28: no initialization handshake or sessions.
Each request supplies protocol version and client capabilities in params._meta.
Use io.modelcontextprotocol/protocolVersion: "2026-07-28" and
io.modelcontextprotocol/clientCapabilities: {} for a client with no capabilities.
Discovery uses server/discover, not initialize; metadata is required per request.
Use stdio (default), or --transport http --listen 127.0.0.1:8080 (/mcp).
HTTP is loopback-only; put authenticated remote access behind an explicit proxy.
HTTP POST /mcp also requires Content-Type: application/json, Accept:
application/json, text/event-stream, matching Mcp-Protocol-Version and Mcp-Method
headers, and Mcp-Name for tool calls. No persistent session or legacy GET/SSE.

Control which tools are exposed via the SCUD_TOOLS env var:
  core (default): tasks, import, update, status, parse
  full: core + sb
  Custom: SCUD_TOOLS=tasks,status,sb

No worker execution, commit, or experimental ensemble tools are exposed.

Usage:
  scud mcp-server [flags]

Examples:
  scud mcp-server
  SCUD_TOOLS=full scud mcp-server
  SCUD_TOOLS=tasks,status scud mcp-server --transport http --listen 127.0.0.1:8080

Flags:
  -h, --help               help for mcp-server
      --listen string      Loopback HTTP listen address (default "127.0.0.1:8080")
      --transport string   Stateless MCP transport: stdio or http (default "stdio")

Global Flags:
  -C, --project string   Change to directory before running
```


## `scud status`

```text
Read a JSON snapshot containing schema_version, revision, phases, summary,
ready references and blocked reasons. Readiness accounts for cross-phase and
inherited dependencies; workflow status is not a verification certificate.

--watch emits an initial snapshot and another on each observed revision change
as JSON lines. This is polling, not an event log or heartbeat, and intermediate
revisions may be missed. --interval is clamped to at least 100ms. Ctrl-C stops
watching; no task is claimed or executed.

Usage:
  scud status [flags]

Examples:
  scud status
  scud status | jq '{revision, summary, ready, blocked}'
  scud status --watch --interval 500ms

Flags:
  -h, --help                help for status
      --interval duration   Poll interval (minimum 100ms) (default 1s)
      --json                Output JSON (the default)
      --watch               Poll snapshots and emit observed revision changes as JSON lines

  -C, --project string   Change to directory before running
```

## `scud update`

```text
Update a task using patch flags OR --input JSON, never both. Use phase:id
or --tag to qualify an ambiguous ID. Omitted fields remain unchanged.

JSON patch fields: status, title, description, details, test_strategy, priority,
complexity, dependencies, assigned_to. --depends-on replaces the entire dependency
list (it does not append); --depends-on= or JSON dependencies: [] clears it.
An empty assigned_to clears the assignee.

Statuses: pending, in-progress, done, failed, blocked, review, expanded, deferred,
cancelled. Priorities: critical, high, medium, low. Status is user-reported,
not proof of verification. Invalid changes leave the task document untouched.
--if-revision compares the current project revision before writing; it is an
optimistic guard, not a lease or exclusive claim. Returns the updated snapshot.

Usage:
  scud update ID [flags]

Examples:
  scud update main:1 --status in-progress
  scud update main:2 --depends-on main:1 --assigned-to alice
  scud update main:2 --depends-on=
  printf '%s\n' '{"test_strategy":"Run tests","dependencies":[]}' | scud update main:2 --input -
  revision=$(scud status | jq -r .revision)
  scud update main:1 --status review --if-revision "$revision"

Flags:
      --assigned-to string     Assignee (empty clears)
      --complexity int         Complexity
      --depends-on strings     Replace dependencies (comma-separated; use --depends-on= to clear)
      --description string     Description
      --details string         Details
  -h, --help                   help for update
      --if-revision string     Expected project revision (optimistic guard, not a lease)
      --input string           JSON patch file or - for stdin
      --json                   Output JSON (the default)
      --priority string        critical, high, medium, low
      --status string          pending, in-progress, done, failed, blocked, review, expanded, deferred, cancelled
      --tag string             Phase tag
      --test-strategy string   Test strategy
      --title string           Title

Global Flags:
  -C, --project string   Change to directory before running
```
